# Polymorphism in Java
-------------------------------
## 1. What is Polymorphism?
**Polymorphism** is one of the fundamental concepts of **Object-Oriented Programming (OOP)**.
The word polymorphism means:
Poly  → Many
Morphism → Forms

# It allows a single method, object, or interface to behave differently depending on the situation or object involved.

Example :A person can have different roles:
Person
  ├── Father
  ├── Husband
  └── Employee
The same person behaves differently depending on the role.
------------------------------------
2. Types of Polymorphism
------------------------------------
Java mainly has two types of polymorphism:

                    Polymorphism
                         |
              ┌──────────┴──────────┐
              ↓                     ↓
       Compile-Time            Runtime
       Polymorphism           Polymorphism
              |                     |
       Method Overloading     Method Overriding

1. Compile-Time Polymorphism
#    * Also called Static Polymorphism
     * Mainly achieved through Method Overloading
2. Runtime Polymorphism
#    * Also called Dynamic Polymorphism
     * Mainly achieved through Method Overriding
------------------------------------
3. Compile-Time Polymorphism
------------------------------------
# Compile-time polymorphism occurs when the method to be executed is determined during compilation.

Key Points:-

* Method selection occurs at compile time.
* Mainly achieved through method overloading.
* Inheritance is not required.
------------------------------------
5. What Does NOT Cause Method Overloading?
------------------------------------
# Changing only the return type does not create method overloading.

Invalid:

class Demo {
    int show(int a) {
        return a;
    }
    double show(int a) {
        return a;
    }
}

# This gives a compilation error because both methods have the same:
Method name
+
Parameter list

Only the return type is different.

# Remember: Return type alone ≠ Method Overloading
------------------------------------
6. Runtime Polymorphism
------------------------------------
# Runtime polymorphism occurs when the method to be executed is determined during program execution.

# It is mainly achieved through: Method Overriding

Key Points

* Method selection occurs at runtime.
* Depends on the actual object type.
* Requires inheritance.
* Achieved through method overriding.
------------------------------------
8. Runtime Polymorphism Example
------------------------------------
class Parent {
    void print() {
        System.out.println("Parent class");
    }
}
class Child extends Parent {
    @Override
    void print() {
        System.out.println("Child class");
    }
}
class Main {
    public static void main(String[] args) {
        Parent p = new Child();
        p.print();
    }
}
Output: Child class
Why? Look carefully:

Parent p = new Child();

Reference type → Parent
Object type    → Child

When: p.print();

is executed, Java calls the method according to the actual object type.

The actual object is: Child

Therefore: Child.print() is executed.

16. Advantages of Polymorphism
------------------------------------
Polymorphism provides several benefits:

1. Flexibility: The same interface or method can work with different objects.

2. Code Reusability: Common code can be reused through parent classes and interfaces.

3. Maintainability: Code becomes easier to modify and extend.

4. Readability: The same method name can represent the same conceptual operation.

5. Extensibility: New subclasses can be added without changing existing code extensively.

6. Supports Abstraction: Polymorphism works closely with:

        Abstraction
        Inheritance
        Interfaces
        Encapsulation

7. Loose Coupling: Code can depend on a parent type/interface instead of a specific implementation.
------------------------------------
17. Disadvantages of Polymorphism
------------------------------------
1. Increased Complexity: Large inheritance hierarchies can become difficult to understand.

2. Debugging Difficulty: Runtime polymorphism can make it harder to determine which implementation is executed.
3. Increased Code Size: Using multiple classes and overridden methods can increase the overall codebase.

4. Runtime Overhead: Runtime method resolution can introduce a small performance overhead.

5. Improper Usage: Poorly designed inheritance and polymorphism can make code harder to maintain.
------------------------------------
18. Real-Life Example

Consider different animals.

              Animal
                 |
        ┌────────┼────────┐
        ↓        ↓        ↓
       Dog      Cat      Cow

Each animal has:

void sound()

But each gives a different implementation.

class Animal {
    void sound() {
        System.out.println("Animal makes sound");
    }
}
class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}
class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Cat meows");
    }
}

Now:

Animal a;
a = new Dog();
a.sound();
a = new Cat();
a.sound();

Output:

Dog barks
Cat meows

Same method call:

a.sound();

Different behavior depending on the actual object.

21. Most Important Interview Points
------------------------------------
Q7. When is an overloaded method selected? Ans: Compile Time

Q8. When is an overridden method selected? Ans: Runtime

Q9. What determines the overridden method at runtime? An: Actual Object Type

# The core distinction to memorize is **`Overloading → Compile Time`** and **`Overriding → Runtime`**. The GFG page also explicitly notes that runtime dispatch depends on the **actual object type, not the reference type**.
