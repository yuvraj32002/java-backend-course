============================================================
        DYNAMIC METHOD DISPATCH IN JAVA
        (RUNTIME POLYMORPHISM)
============================================================
1. WHAT IS DYNAMIC METHOD DISPATCH?
------------------------------------
# Dynamic Method Dispatch is the mechanism in Java by which a call to an overridden method is resolved at RUNTIME rather than at COMPILE TIME. It is the mechanism through which Java achieves RUNTIME POLYMORPHISM.

In simple words:

    Parent reference
          ↓
    Child object
          ↓
    Overridden method
          ↓
    Decided at RUNTIME
============================================================
2. OTHER NAMES
============================================================
Dynamic Method Dispatch is also known as:

    • Runtime Method Dispatch
    • Runtime Polymorphism
    • Dynamic Binding
    • Late Binding

These terms are closely related to the same runtime method-selection
mechanism.
============================================================
3. REQUIREMENTS FOR DYNAMIC METHOD DISPATCH
============================================================
Dynamic Method Dispatch generally requires:

    1. Inheritance
    2. Method Overriding
    3. Parent/Superclass reference
    4. Child/Subclass object
    5. Instance method call


Basic structure:

    Parent ref = new Child();
    ref.method();
============================================================
6. MAIN EXAMPLE
============================================================

    class A {

        void m1() {
            System.out.println("Inside A's m1 method");
        }
    }


    class B extends A {

        @Override
        void m1() {
            System.out.println("Inside B's m1 method");
        }
    }


    class C extends A {

        @Override
        void m1() {
            System.out.println("Inside C's m1 method");
        }
    }


    class Dispatch {

        public static void main(String[] args) {

            A a = new A();
            B b = new B();
            C c = new C();

            A ref;

            ref = a;
            ref.m1();

            ref = b;
            ref.m1();

            ref = c;
            ref.m1();
        }
    }


Output:

    Inside A's m1 method
    Inside B's m1 method
    Inside C's m1 method
============================================================
8. KEY CONCEPT: REFERENCE TYPE vs OBJECT TYPE
============================================================
This is the MOST IMPORTANT concept in Dynamic Method Dispatch.
Example:

    Animal a = new Dog();


Here:

    Animal → Reference Type
    Dog    → Object Type / Actual Type


For overridden instance methods:

    Method execution → decided by OBJECT TYPE


Therefore:

    Animal a = new Dog();
    a.sound();

Result:

    Dog.sound()


NOT:

    Animal.sound()


------------------------------------------------------------

Remember:

    Reference Type
          ↓
    Decides what members can be accessed

    Object Type
          ↓
    Decides which overridden instance method executes


============================================================
9. UPCASTING
============================================================

Dynamic Method Dispatch commonly uses UPCASTING.

Upcasting means assigning a child class object to a parent class
reference.

Syntax:

    Parent ref = new Child();


Example:

    Animal a = new Dog();


Here:

    Dog object
        ↓
    Animal reference

This is called UPCASTING.


Why is upcasting important?

Because it allows a parent reference to refer to different child objects.

Example:

    Animal a;

    a = new Dog();
    a.sound();

    a = new Cat();
    a.sound();


Output:

    Dog barks
    Cat meows


Same reference:

    Animal a

Different objects:

    Dog
    Cat

Different overridden methods are executed at runtime.

10. REAL IDEA BEHIND DYNAMIC POLYMORPHISM
============================================================

Suppose we have:

    Animal
      |
      |---- Dog
      |
      |---- Cat
      |
      |---- Cow


Each class has:

    sound()


Dog:

    sound() → Bark

Cat:

    sound() → Meow

Cow:

    sound() → Moo


We can write:

    Animal a;

    a = new Dog();
    a.sound();

    a = new Cat();
    a.sound();

    a = new Cow();
    a.sound();


Output:

    Bark
    Meow
    Moo


The same reference:

    Animal a

can represent different objects.

This is POLYMORPHISM.


============================================================
11. DYNAMIC METHOD DISPATCH vs METHOD OVERRIDING
============================================================

METHOD OVERRIDING:

    Child class provides its own implementation of a method
    already present in the parent class.

DYNAMIC METHOD DISPATCH:

    Java decides at runtime which overridden method should execute
    based on the actual object.


Relationship:

    Method Overriding
          ↓
    Enables Runtime Polymorphism
          ↓
    Dynamic Method Dispatch
          ↓
    Method selected at Runtime


============================================================
12. DYNAMIC METHOD DISPATCH vs METHOD OVERLOADING
============================================================

    Feature              Overloading          Dynamic Dispatch
    ---------------------------------------------------------------
    Polymorphism         Compile-time         Runtime
    Also called          Static               Dynamic
    Binding              Early                Late
    Main concept         Overloading          Overriding
    Inheritance          Not required         Required
    Method signature     Different             Same
    Decision time        Compile time         Runtime
    Based on             Arguments             Actual object


Example of Overloading:

    void show(int x)
    void show(double x)


Example of Dynamic Dispatch:

    Parent ref = new Child();
    ref.show();


============================================================
13. STATIC BINDING vs DYNAMIC BINDING
============================================================

STATIC / EARLY BINDING:

    Method call is resolved at compile time.

Example:

    Method Overloading


DYNAMIC / LATE BINDING:

    Method call is resolved at runtime.

Example:

    Method Overriding


Flow:

    OVERLOADING
        ↓
    Compile Time
        ↓
    Static Binding


    OVERRIDING
        ↓
    Runtime
        ↓
    Dynamic Binding


============================================================
14. RUNTIME POLYMORPHISM
============================================================

Runtime Polymorphism is polymorphism where the method that should execute
is determined during runtime.

It is achieved through METHOD OVERRIDING and Dynamic Method Dispatch.


Example:

    class Parent {

        void show() {
            System.out.println("Parent");
        }
    }


    class Child extends Parent {

        @Override
        void show() {
            System.out.println("Child");
        }
    }


    public class Main {

        public static void main(String[] args) {

            Parent p = new Child();

            p.show();
        }
    }


Output:

    Child


Reason:

    Reference Type = Parent
    Object Type    = Child

Therefore:

    Child.show() executes.


============================================================
15. IMPORTANT: DATA MEMBERS ARE NOT POLYMORPHIC
============================================================

In Java, VARIABLES / DATA MEMBERS are NOT overridden.

Only methods participate in method overriding.

Example:

    class A {

        int x = 10;
    }


    class B extends A {

        int x = 20;
    }


    class Main {

        public static void main(String[] args) {

            A a = new B();

            System.out.println(a.x);
        }
    }


Output:

    10


Why?

Because variables are resolved according to the REFERENCE TYPE.

Here:

    Reference Type = A

Therefore:

    a.x → A.x


NOT:

    B.x


IMPORTANT:

    Methods  → Runtime / Object Type
    Variables → Reference Type


============================================================
16. METHOD vs DATA MEMBER
============================================================

Consider:

    class A {

        int x = 10;

        void show() {
            System.out.println("A");
        }
    }


    class B extends A {

        int x = 20;

        @Override
        void show() {
            System.out.println("B");
        }
    }


    A obj = new B();


For variable:

    obj.x

Result:

    10


For method:

    obj.show()

Result:

    B


Therefore:

    obj.x
       ↓
    Reference type → A.x


    obj.show()
       ↓
    Actual object → B.show()


============================================================
17. WHAT CANNOT BE OVERRIDDEN?
============================================================

The following methods cannot participate in normal method overriding:

    1. final methods
    2. static methods
    3. private methods


------------------------------------------------------------
A. FINAL METHOD
------------------------------------------------------------

A final method cannot be overridden by a subclass.

Example:

    class Parent {

        final void show() {
            System.out.println("Parent");
        }
    }


    class Child extends Parent {

        // ERROR
        // void show() { }
    }


Reason:

    final method → cannot be overridden


------------------------------------------------------------
B. STATIC METHOD
------------------------------------------------------------

Static methods are not overridden.

If a child declares a static method with the same signature,
it is METHOD HIDING, not overriding.


Example:

    class Parent {

        static void show() {
            System.out.println("Parent");
        }
    }


    class Child extends Parent {

        static void show() {
            System.out.println("Child");
        }
    }


    Parent p = new Child();

    p.show();


Output:

    Parent


Because static method calls are resolved using the reference/class
rather than runtime dynamic dispatch.


------------------------------------------------------------
C. PRIVATE METHOD
------------------------------------------------------------

Private methods are not inherited by subclasses and therefore cannot
be overridden.

A method with the same name in the child is a separate method.


============================================================
18. ACCESS MODIFIER AND OVERRIDING
============================================================

When overriding a method:

    Child method cannot have a MORE RESTRICTIVE access modifier
    than the parent method.


Example:

    Parent:

    public void show()


Child cannot do:

    private void show()    ❌
    protected void show()  ❌


But it can do:

    public void show()     ✅


General rule:

    Child method access >= Parent method access


Also:

    public    → most accessible
    protected → less accessible
    default   → package-level
    private   → least accessible


============================================================
19. RETURN TYPE IN OVERRIDING
============================================================

An overridden method must have the same return type or a
COVARIANT RETURN TYPE.


Example:

    class Parent {

        Object getValue() {
            return new Object();
        }
    }


    class Child extends Parent {

        @Override
        String getValue() {
            return "Hello";
        }
    }


This is allowed because:

    String IS-A Object


This is called COVARIANT RETURN TYPE.


============================================================
20. @Override ANNOTATION
============================================================

The @Override annotation tells the compiler that a method is intended
to override a method from the parent class/interface.


Example:

    class Dog extends Animal {

        @Override
        void sound() {
            System.out.println("Bark");
        }
    }


Advantages:

    • Makes programmer's intention clear
    • Helps compiler detect overriding mistakes
    • Prevents accidental overloading
    • Improves readability
    • Improves maintainability


NOTE:

    @Override is not mandatory for overriding to work.

But it is strongly recommended.


============================================================
21. ADVANTAGES OF DYNAMIC METHOD DISPATCH
============================================================

1. RUNTIME POLYMORPHISM
   --------------------------------
   Method implementation can be selected at runtime.


2. FLEXIBILITY
   --------------------------------
   One parent reference can refer to different child objects.


3. CODE REUSABILITY
   --------------------------------
   Common code can work with multiple related classes.


4. EXTENSIBILITY
   --------------------------------
   New subclasses can be added without changing existing
   polymorphic code in many cases.


5. REDUCED CONDITIONAL LOGIC
   --------------------------------
   Reduces the need for large if-else or switch structures
   based on object types.


6. LOOSE COUPLING
   --------------------------------
   Code can depend on a superclass/interface rather than a
   specific implementation.

22. REAL-WORLD EXAMPLE
============================================================

Suppose we have:

    Payment
       |
       |---- UPI
       |
       |---- CreditCard
       |
       |---- Cash


Each class implements:

    pay()


Example:

    Payment p;

    p = new UPI();
    p.pay();

    p = new CreditCard();
    p.pay();

    p = new Cash();
    p.pay();


The same reference:

    Payment p

can refer to different payment objects.

The correct pay() implementation is selected at runtime.


This makes the system easier to extend.

For example, we can later add:

    Payment
       |
       |---- UPI
       |---- CreditCard
       |---- Cash
       |---- NetBanking


without changing the basic polymorphic structure.

23. IMPORTANT INTERVIEW CONCEPT
============================================================

Question:

    Animal a = new Dog();

    Which type determines the method that executes?

Answer:

    ACTUAL OBJECT TYPE determines the overridden instance method.

Here:

    Reference Type = Animal
    Object Type    = Dog

Therefore:

    Dog's overridden method executes.

24. VERY IMPORTANT RULES
============================================================

Remember these rules:

    Rule 1:
    Dynamic Method Dispatch works with METHOD OVERRIDING.


    Rule 2:
    It is a form of RUNTIME POLYMORPHISM.


    Rule 3:
    It uses DYNAMIC/LATE BINDING.


    Rule 4:
    Parent reference can refer to child object.


    Rule 5:
    Overridden instance method is selected according to
    the ACTUAL OBJECT TYPE.


    Rule 6:
    Data members are NOT overridden.


    Rule 7:
    Variables are accessed according to REFERENCE TYPE.


    Rule 8:
    static methods are hidden, not overridden.


    Rule 9:
    final methods cannot be overridden.


    Rule 10:
    private methods cannot be overridden.


    Rule 11:
    @Override is recommended for detecting overriding mistakes.
