========================================
       METHOD OVERLOADING IN JAVA
========================================
1. WHAT IS METHOD OVERLOADING?
--------------------------------
# Method Overloading means defining multiple methods with the SAME METHOD NAME but DIFFERENT PARAMETER LISTS inside a class.
Example: 
class Calculator {
    int add(int a, int b) {
        return a + b;
    }
    int add(int a, int b, int c) {
        return a + b + c;
    }
    double add(double a, double b) {
        return a + b;
    }
}
# Method overloading is an example of COMPILE-TIME POLYMORPHISM.
========================================
2. RULES OF METHOD OVERLOADING
========================================
For method overloading:
# 1. Method name must be SAME.
# 2. Parameter list must be DIFFERENT.
# Parameters can differ in: a) NUMBER of parameters
#                           b) DATA TYPE of parameters
#                           c) ORDER of parameters
# IMPORTANT:Changing ONLY the return type does NOT constitute method overloading.
Example:
int add(int a, int b) {
    return a + b;
}
double add(int a, int b) {
    return a + b;
}
This is NOT valid method overloading.
Reason:
Both methods have exactly the same parameter list:
add(int, int)
Only the return type is different.
# Therefore:
# Same name
+
# Same parameters
+
# Different return type
=
# NOT METHOD OVERLOADING

========================================
3.3 CHANGING ORDER OF PARAMETERS
========================================
Methods can also be overloaded by changing
the ORDER of parameters.
Example:
class Student {
    public void studentId(String name, int rollNo) {
        System.out.println(
            "Name: " + name +
            ", Roll-No: " + rollNo
        );
    }
    public void studentId(int rollNo, String name) {
        System.out.println(
            "Roll-No: " + rollNo +
            ", Name: " + name
        );
    }
}
Here:
studentId(String, int)
and
studentId(int, String)
have the same number of parameters
and the same parameter types,
BUT their ORDER is different.
Therefore, they are overloaded methods.
Calling:
Student s = new Student();
s.studentId("Sweta", 1);
s.studentId(2, "Gudly");
The compiler identifies the correct method
based on the order and type of arguments.
Key Point:
Same method name
+
Different ORDER of parameters
=
METHOD OVERLOADING
========================================
4. HYBRID METHOD OVERLOADING
========================================
More than one characteristic of the
parameter list can be different.
For example:
void show(int a, double b)
void show(double a, int b, String c)
Here:
1. Number of parameters is different.
2. Data types are different.
3. Order is different.
Therefore, these methods are overloaded.
========================================
5. HOW DOES JAVA CHOOSE AN
   OVERLOADED METHOD?
========================================
When an overloaded method is called,
the compiler examines the arguments
passed to the method.
PROCESS:
Method call
    ↓
Compiler checks arguments
    ↓
Finds compatible overloaded method
    ↓
Selects appropriate method
    ↓
Method executes
========================================
# 6. WHAT IF EXACT PARAMETER TYPE DOES NOT MATCH?
========================================
# Sometimes an exact method is not available. Java can perform certain METHOD INVOCATION CONVERSIONS, especially primitive widening conversions, to find a compatible method.
Example:
class Demo {
    public void show(int x) {
        System.out.println("In int: " + x);
    }
    public void show(String s) {
        System.out.println("In String: " + s);
    }
    public void show(byte b) {
        System.out.println("In byte: " + b);
    }
}
Demo obj = new Demo();
obj.show((byte) 25);
obj.show("hello");
obj.show(250);
obj.show('A');
Output:
In byte: 25
In String: hello
In int: 250
# In int: 65
========================================
7. UNDERSTANDING EACH CALL
========================================
CASE 1:
obj.show((byte) 25);
The argument is explicitly a byte.
Therefore Java chooses:
show(byte)
----------------------------------------
CASE 2:
obj.show("hello");
The argument is a String.
Therefore Java chooses:
show(String)
----------------------------------------
CASE 3:
obj.show(250);
An integer literal such as 250 is normally
treated as an int.
Therefore Java chooses:
show(int)
----------------------------------------
# CASE 4:
obj.show('A');
# A' is a char.
# Java can widen:
# char -> int
# Therefore Java chooses:
# show(int)
# The Unicode value of 'A' is: 65. Therefore output: => In int: 65
----------------------------------------
CASE 5:
obj.show(7.5);
# 7.5 is a double.
Available methods are:
show(int)
show(String)
show(byte)
# There is no show(double).
# Java does not automatically narrow: double -> int or double -> byte
# Therefore this results in a COMPILATION ERROR.
========================================
8. PRIMITIVE WIDENING IN OVERLOADING
========================================
# Java can perform certain widening conversions. Common widening conversions:
# byte -> short -> int -> long -> float -> double
# char -> int -> long -> float -> double
========================================
10. IMPORTANT EXAM / INTERVIEW POINTS
========================================
1. Method overloading means multiple methods
   with the same name but different parameter lists.
2. Method overloading is compile-time polymorphism.
3. Parameters can differ by:
   - Number
   - Type
   - Order
4. Return type alone cannot overload a method.
5. Overloading commonly occurs within the same class.
6. The compiler determines which overloaded method
   should be called.
7. # Java may use primitive widening conversions when finding a compatible overloaded method.
8. # Java does not automatically perform narrowing conversions such as: double -> int
9. # char can be widened to int.
