1. WHAT IS JDK?
========================================
JDK stands for: Java Development Kit

# JDK is a software package used to:

# • Develop Java applications
# • Compile Java programs
# • Run Java programs
# • Debug Java programs
# • Package Java applications

# In simple words: JDK = Tools required to DEVELOP Java applications

# IMPORTANT: JDK = JRE + Development Tools

# JRE(JAVA RUNTIME ENVIRONMENT):-

1. WHAT IS JRE?
----------------------------------------
JRE = Java Runtime Environment
JRE provides the environment required
to RUN Java applications.
JRE contains:
    JVM
     +
    Java Class Libraries
     +
    Supporting Files
IMPORTANT:
JRE is mainly responsible for
EXECUTING Java Bytecode.
========================================
3. MAIN COMPONENTS OF JRE
========================================
1. JVM
   → Executes Java Bytecode.
2. Class Libraries
   → Provide pre-built classes and APIs.
3. Integration Libraries
   → Support database and remote-system
     communication.
   → Example: JDBC, JNDI, RMI
4. UI Libraries
   → Used for GUI applications.
   → Example: AWT, Swing, Java 2D
5. Base Libraries
   → Provide core Java functionality.
   → Example: java.lang, java.util
6. Supporting Libraries
   → Provide additional functionality.
   → Example: JNI, JMX, Networking APIs

# Main responsibilities:

• Execute bytecode
• Manage memory
• Perform Garbage Collection

# 4. CLASS LOADER SUBSYSTEM
========================================
# Responsible for loading .class files into memory.
# It performs 3 main activities:
1. Loading
2. Linking
3. Initialization
# LOADING
--------
Loads the binary representation of a class into memory.

# LINKING
-------
Linking has 3 steps:
1. # Verification
   → Checks whether bytecode is valid
     and safe.
2. # Preparation
   → Allocates memory for static variables
     and assigns default values.
3. # Resolution
   → Converts symbolic references into
     direct references.
# INITIALIZATION
--------------
• Assigns actual values to static variables.
• Executes static blocks.
========================================
5. TYPES OF CLASS LOADERS
========================================
1. Bootstrap Class Loader
   → Loads core Java classes.
2. Platform/Extension Class Loader
   → Loads platform/extension classes.
3. Application/System Class Loader
   → Loads classes from the application
     classpath.
========================================
6. JVM MEMORY AREAS
========================================
JVM memory is divided into:
1. Method Area
2. Heap
3. Stack
4. PC Register
5. Native Method Stack
----------------------------------------
# METHOD AREA
----------------------------------------
Stores class-level information such as:
• Class information
• Methods
• Static variables
• Other class metadata
Shared among threads.
----------------------------------------
# HEAP
----------------------------------------
Stores:
• Objects
• Instance data
Shared among threads.
Example:
Computer obj = new Computer();
The Computer object is created
in the Heap.
----------------------------------------
# STACK
----------------------------------------
Each thread has its own stack.
Stores:
• Method calls
• Local variables
• Stack frames
# Stack is destroyed when the thread terminates.
----------------------------------------
# PC REGISTER
----------------------------------------
PC = Program Counter
Stores the address/information of
the currently executing instruction
for each thread.
----------------------------------------
# NATIVE METHOD STACK
----------------------------------------
# Each thread has a separate stack for executing native methods.
========================================
# 7. EXECUTION ENGINE
========================================
Execution Engine executes Java Bytecode.
It contains:
1. Interpreter
2. JIT Compiler
3. Garbage Collector
----------------------------------------
# INTERPRETER
----------------------------------------
# Reads and executes bytecode instruction by instruction.
Problem:
# If the same code runs repeatedly, it may need to be interpreted again and again.
----------------------------------------
# JIT COMPILER
----------------------------------------
JIT = Just-In-Time Compiler
# It improves performance by compiling frequently executed bytecode into native machine code. So repeated code can execute faster.
# Flow:
Bytecode
   ↓
Interpreter
   ↓
Frequently used code
   ↓
JIT Compiler
   ↓
Native Machine Code
   ↓
Faster Execution
----------------------------------------
# GARBAGE COLLECTOR
----------------------------------------
# Automatically removes objects that are no longer referenced/needed.
Purpose:
# Free unused Heap memory.
========================================
# 8. JNI
========================================
JNI = Java Native Interface
JNI allows Java code running inside
the JVM to interact with native code
written in languages such as:
• C
• C++
========================================
# 9. NATIVE METHOD LIBRARIES
========================================
These are libraries containing
native code required by the JVM
or Java applications.
They are commonly written in:
• C
• C++

• Linking = Verification + Preparation
  + Resolution.
• Initialization executes static blocks
  and assigns actual static values.
• Heap stores objects.
• Stack stores method calls and
  local variables.
• Method Area stores class-level data.

  instruction for each thread.

  instruction by instruction.

  unreferenced objects.
