JAVA STRINGS:
---------------------------------------------------------------------------------
1. What is a String?

A String in Java is an object used to store a sequence of characters.

String name = "Geeks";
String num = "1234";

Important Points:-

* String is a class, not a primitive data type.
* A String stores a sequence of characters.
* String literals are written inside double quotes " ".
* Java Strings use Unicode character encoding.
* Strings are immutable.
* Java provides many built-in methods for:
    * Searching
    * Comparing
    * Concatenating
    * Extracting
    * Manipulating text
---------------------------------------------------------------------------------
2. Ways to Create a String:-
---------------------------------------------------------------------------------
There are mainly two ways to create a String:-
A. Using String Literal :-
-------------------------
String str = "GeeksforGeeks";

A String literal is stored in the String Pool.

If the same String already exists in the pool, Java can reuse that existing String object.

Example

String s1 = "Hello";
String s2 = "Hello";

Both references can point to the same String Pool object.

Conceptually:

        String Pool
       ┌───────────┐
       │  "Hello"  │
       └───────────┘
          ↑     ↑
          │     │
         s1    s2
Advantage:
It saves memory because Java can reuse an existing String object instead of creating another identical object.
------------------------------------
3. Using the new Keyword
------------------------------------
A String can also be created using new.

String str = new String("GeeksforGeeks");

Using new explicitly creates a new String object on the heap.

The literal "GeeksforGeeks" may also exist in the String Pool if it is not already there.
Example:
String s1 = new String("Hello");
String s2 = new String("Hello");

Here:
* s1 refers to one heap String object.
* s2 refers to another heap String object.
* The "Hello" literal is associated with the String Pool.

Conceptually:

String Pool
┌─────────┐
│ "Hello" │
└─────────┘
Heap
┌─────────┐       ┌─────────┐
│ "Hello" │       │ "Hello" │
└─────────┘       └─────────┘
     ↑                 ↑
     s1                s2

Key Difference

String s1 = "Hello";

→ Uses/reuses the String Pool.

String s2 = new String("Hello");

→ Creates a new String object on the heap.

5. String Immutability
---------------------------------------------------------------------------------------------------
What does Immutable mean?
Immutable = Cannot be changed after creation.
Once a String object is created, its contents cannot be modified.
If we perform an operation that appears to change a String, Java actually creates a new String object.

Example
public class GFG {
    public static void main(String[] args) {
        String str = "Hello";
        str.concat(" World");
        System.out.println(str);
    }
}

Output

Hello

Why?

str.concat(" World");

does NOT modify the original "Hello" object.

Conceptually:

Original String
"Hello"
   │
   │ concat(" World")
   ↓
"Hello World"

A new String "Hello World" is created.
But because we did not store the returned String:

str.concat(" World");

the new String is not assigned to str.

Therefore:
str still refers to: "Hello"

⸻
Correct Way: If we want to store the modified String:

String str = "Hello";
str = str.concat(" World");
System.out.println(str);

str now refers to the new String object.

7. String Pool
---------------------------------------------------------------------------------------------------
The String Pool, also called the String Constant Pool, is a special area used for storing String literals.
It is part of the heap memory in modern Java.

Example
String s1 = "Hello";

The literal: "Hello" is stored in the String Pool. The reference s1 points to that pooled String.

Stack                  Heap
                    ┌─────────────┐
s1 ───────────────→ │ String Pool │
                    │   "Hello"   │
                    └─────────────┘

9. new String() and Memory
---------------------------------------------------------------------------------------------------
Consider:

String s1 = new String("John");
String s2 = new String("Deo");

The new keyword creates String objects on the heap.
The literals:

"John"
"Deo"

are also stored in the String Pool if they are not already present.
So there can be:

String Pool
┌────────┐
│ "John" │
├────────┤
│ "Deo"  │
└────────┘
Heap
┌────────┐
│ "John" │ ← s1
├────────┤
│ "Deo"  │ ← s2
└────────┘

10. intern() Method
---------------------------------------------------------------------------------------------------
The intern() method is used to obtain the canonical String reference from the String Pool.

Example

String internedString = demoString.intern();

If an equal String already exists in the String Pool:

existing pooled String
        ↑
        │
    intern()
        ↑
    demoString

the existing pooled reference is returned.

If it does not exist, an appropriate pooled String is added and its reference is returned.

Basic Idea

String object
     │
     │ intern()
     ↓
String Pool reference

13. String Pool Migration
---------------------------------------------------------------------------------------------------
There was an important change in Java’s memory organization.

Before Java 7

The String Pool was located in the PermGen area.

Before Java 7
Heap
 │
 └── Objects
PermGen
 │
 └── String Pool

Java 7 onwards

The String Pool was moved to the normal heap.

Java 7+
Heap
 │
 ├── Normal Objects
 │
 └── String Pool

Benefits

Moving the String Pool to the heap:

* Allowed the String Pool to be managed as part of heap memory.
* Reduced limitations associated with the old PermGen-based implementation.
* Allowed the Garbage Collector to manage pooled Strings as heap objects.

15. Stack vs Heap — Basic Understanding
---------------------------------------------------------------------------------------------------
When discussing Strings, remember the distinction between:

Reference Variable

The reference variable can exist in the stack when it is a local variable.

String Object

The String object itself exists in the heap.

Example:

String s = "Hello";

Conceptually:

STACK                     HEAP
┌─────────┐              ┌─────────┐
│    s ───┼────────────→ │ "Hello" │
└─────────┘              └─────────┘
                          String Pool

The exact JVM implementation is more sophisticated, so this diagram should be treated as a conceptual model rather than a literal representation of JVM memory addresses.
---------------------------------------------------------------------------------------------------
16. Java 9+ Compact Strings — Important Note
---------------------------------------------------------------------------------------------------
Modern Java implementations use Compact Strings internally.

Instead of assuming every String is physically stored as a simple char[], modern JVMs can use a compact representation based on:

byte[] + coder information

This can reduce memory usage for strings that can be represented efficiently.

Therefore, diagrams showing a String as:

String
 ↓
char[]
 ↓
characters

are useful for conceptual understanding, but they should not be interpreted as the exact current JVM object layout.
