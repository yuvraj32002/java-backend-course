1. WHAT IS GIT?

Git is a Distributed Version Control System (DVCS) used to
track changes in a project.

It helps us:

• Track code changes
• Save different versions of a project
• Work with branches
• Go back to previous versions
• Collaborate with other developers

Simple idea:

Project → Changes → Git tracks every important version

============================================================
2. VERSION CONTROL

Version Control System (VCS) manages different versions of
files/projects.

Without Git:

file_v1
file_v2
file_final
file_final2
file_final_final

With Git:

Commit 1 → Commit 2 → Commit 3 → Commit 4

Each commit represents a recorded version of the project.

TYPES OF VERSION CONTROL:

1. Local VCS
2. Centralized VCS
3. Distributed VCS

Git is:

Distributed Version Control System (DVCS)
============================================================
3. HISTORY OF GIT

Git was created by Linus Torvalds in 2005.

It was originally developed for managing the source code
of the Linux kernel.

Git was designed to be:

• Fast
• Distributed
• Reliable
• Suitable for large projects

IMPORTANT:

Git ≠ GitHub

Git:
Version control software

GitHub:
Online platform for hosting Git repositories

4. GIT SETUP

Check whether Git is installed:

git --version

Example:

git version 2.x.x

Configure your identity:

git config --global user.name "Yuvraj Kumar"
git config --global user.email "your-email@example.com"

Check configuration:

git config --list

WHY?

Git uses your name and email to identify the author of
commits.

5. GIT INIT

To start using Git inside a project:

git init

Example:

mkdir git-course
cd git-course
git init

This creates a hidden:

.git

directory.

.git contains Git’s internal information such as:

• Commit history
• Branch information
• Configuration
• References

IMPORTANT:

git init
    ↓
Converts a normal folder
into a Git repository.

6. BASIC GIT WORKFLOW

Git mainly works through these stages:

Working Directory
      ↓
   git add
      ↓
Staging Area
      ↓
  git commit
      ↓
Local Repository

Example:

file.txt
   ↓
git add file.txt
   ↓
Staging Area
   ↓
git commit -m "Add file"
   ↓
Git Repository

============================================================
7. GIT COMMIT

A commit is a recorded snapshot of changes.

First check:

git status

Add file:

git add file.txt

Commit:

git commit -m "Add file.txt"

Or:

git add .
git commit -m "Initial commit"

Meaning:

git add
    → Prepare changes
git commit
    → Permanently record those staged changes
      in the local Git history.

VIEW COMMIT HISTORY:

git log

Short version:

git log --oneline

============================================================
8. SKIPPING THE STAGING AREA

Normally:

Working Directory
      ↓
   git add
      ↓
   Staging
      ↓
  git commit

For already tracked files, we can combine add + commit:

git commit -am "Update file"

Here:

-a → automatically stages modified/deleted
     tracked files
-m → commit message

IMPORTANT:

git commit -am

does NOT add completely new/untracked files.

For a new file:

git add newfile.txt
git commit -m "Add new file"

============================================================
9. GIT DIFF

git diff shows changes that have been made but are not
yet staged.

Command:

git diff

Flow:

Modify file
    ↓
git diff
    ↓
See changes
    ↓
git add .
    ↓
Changes become staged

To see staged changes:

git diff --staged

Simple difference:

git diff
    → Working Directory vs Staging Area
git diff --staged
    → Staging Area vs Last Commit

============================================================
10. REMOVE A FILE

To remove a tracked file using Git:

git rm file.txt

This:

• Deletes the file
• Stages the deletion

Then commit:

git commit -m "Remove file.txt"

If you delete a file manually:

rm file.txt

Git detects the deletion with:

git status

Then stage it:

git add -u

or:

git rm file.txt

11. GITHUB REPOSITORY

GitHub is an online platform where Git repositories can
be stored and shared.

Think:

Local Git Repository
        ↕
      GitHub
   Remote Repository

Common terms:

Local Repository
    → Repository on your computer
Remote Repository
    → Repository hosted on GitHub

============================================================
12. CONNECT LOCAL REPOSITORY TO GITHUB

Create a repository on GitHub.

Then connect your local repository:

git remote add origin <repository-link>

Example:

git remote add origin git@github.com:
username/project.git

Check remote:

git remote -v

Here:

origin
    → Name/alias of the remote repository
URL
    → Address of the GitHub repository

============================================================
13. PUSH LOCAL PROJECT TO GITHUB

First make sure your branch is named main:

git branch -M main

Then push:

git push -u origin main

Meaning:

git push
    → Send local commits to remote
origin
    → Remote repository
main
    → Branch being pushed
-u
    → Sets upstream tracking

After upstream is set, future pushes can usually be:

git push

BASIC FLOW:

Local Project
    ↓
git add .
    ↓
git commit
    ↓
git push
    ↓
GitHub

============================================================
14. GIT TAGS

A tag is a name/reference given to a specific commit.

Tags are commonly used for versions.

Examples:

v1.0
v1.1
v2.0

Create an annotated tag:

git tag -a v1.0 -m "First stable version"

Check tags:

git tag

Show tag details:

git show v1.0

Push tag to GitHub:

git push origin v1.0

Push all tags:

git push origin --tags

IMPORTANT:

A tag normally stays attached to the specific commit where
it was created.

Example:

A ---- B ---- C ---- D ---- E
               ↑
              v1.0

Even if main moves to E, v1.0 still points to C.

============================================================
15. CLONE A PROJECT

git clone downloads an existing Git repository from a
remote location to your computer.

Command:

git clone <link>

Example:

git clone git@github.com:username/project.git

Then:

cd project

Clone automatically:

• Downloads project files
• Downloads Git history
• Creates a local Git repository
• Connects the local repository to the remote

Check remote:

git remote -v

Typical flow:

GitHub Repository
      ↓
  git clone
      ↓
Local Repository

============================================================
16. FORK vs CLONE

FORK:

GitHub → Your GitHub account

CLONE:

GitHub → Your computer

Example contribution flow:

Original GitHub Repository
          ↓
        Fork
          ↓
   Your GitHub Repository
          ↓
        Clone
          ↓
   Your Computer

17. GIT BRANCH

A branch is an independent line of development.

Branches allow us to work on features/fixes without directly
changing the main branch.

Example:

A ---- B ---- C ---- D
               \
                E ---- F
                ↑
             feature

main:
A → B → C → D

feature:
C → E → F

============================================================
18. CREATE A BRANCH

Create a branch:

git branch feature

Switch to it:

git switch feature

OR create and switch in one command:

git switch -c feature

Older alternative:

git checkout -b feature

Check branches:

git branch

The branch with * is the currently active branch.

Example:

* feature
  main

============================================================
19. HOW BRANCHES WORK

Suppose:

A ---- B ---- C
               ↑
              main

Create feature branch:

A ---- B ---- C
               \
                D ---- E
                ↑
             feature

Now:

main
  ↓
  C
feature
  ↓
  E

Branches are essentially references/pointers to commits.

The important idea:

Branch = movable pointer to a commit

============================================================
20. DELETE A BRANCH

Delete a local branch:

git branch -d feature

Force delete:

git branch -D feature

IMPORTANT:

You generally cannot delete the branch you are currently
working on.

First switch to another branch:

git switch main

Then:

git branch -d feature

============================================================
21. PUSH A BRANCH TO GITHUB

Creating a branch locally does not automatically create
that branch on GitHub.

Push it:

git push -u origin feature

After that:

git push

Flow:

Local feature branch
        ↓
   git push -u
        ↓
GitHub feature branch

============================================================
22. GIT MERGE

Merge combines the changes/history of one branch into
another branch.

Example:

main:
A ---- B ---- C
                \
feature:         D ---- E

To merge feature into main:

git switch main
git merge feature

Result:

main
  ↓
A ---- B ---- C ---- D ---- E

The feature branch can now be deleted if it is no longer
needed:

git branch -d feature

============================================================
23. COMPLETE BRANCH WORKFLOW

Create branch:

Make changes.

Check changes:

git status
git diff

Stage:

Commit:

git commit -m "Add feature"

Push branch:

git push
