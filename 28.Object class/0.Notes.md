 OBJECT CLASS IN JAVA — CLASS NOTES
────────────────────────────────────────────────────────────
1. Introduction to Object Class

Object is the root class of Java’s class hierarchy. Every class in Java directly or indirectly inherits from the Object class.

Therefore:

                    Object
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
       Class A      Class B      Class C
          │
          ↓
       SubClass

If a class does not explicitly extend another class, it implicitly extends Object.
Example:

class Student {
    int id;
    String name;
}

Internally, it is treated as:

class Student extends Object {
    int id;
    String name;
}

Hence, an object of Student can use the methods inherited from Object.
────────────────────────────────────────────────────────────
2. Why is Object Class Important?

The Object class provides a set of common methods that can be used by objects of all Java classes. These methods are useful for:

Object Class
     │
     ├── Comparing objects
     │      → equals()
     │
     ├── Representing objects as text
     │      → toString()
     │
     ├── Generating hash values
     │      → hashCode()
     │
     ├── Finding runtime class
     │      → getClass()
     │
     ├── Object cloning
     │      → clone()
     │
     └── Thread synchronization
            → wait()
            → notify()
            → notifyAll()
────────────────────────────────────────────────────────────
3. Methods of Object Class
────────────────────────────────────────────────────────────
The important methods provided by Object are:

Method	Purpose
toString()	Returns a string representation of an object
equals()	Compares two objects
hashCode()	Returns a hash value for an object
getClass()	Returns the runtime class of an object
clone()	    Creates a copy of an object
finalize()	Historically associated with object cleanup; deprecated
wait()	    Makes the current thread wait
notify()	Wakes one waiting thread
notifyAll()	Wakes all waiting threads
────────────────────────────────────────────────────────────
4. toString() Method
────────────────────────────────────────────────────────────
Syntax: public String toString()

The toString() method returns a string representation of an object. It is commonly overridden so that an object can display meaningful information instead of the default representation.

Example

class Student {
    int id = 101;
    String name = "Yuvraj";
    public String toString() {
        return id + " " + name;
    }
}
class Main {
    public static void main(String[] args) {
        Student s = new Student();
        System.out.println(s);
    }
}
Output: 101 Yuvraj

When an object is passed to System.out.println(), Java can invoke its toString() method.
────────────────────────────────────────────────────────────
5. equals() Method
────────────────────────────────────────────────────────────
Syntax: public boolean equals(Object obj)

# The equals() method is used to determine whether two objects are equal. The default implementation in Object compares object references.
Example: 

Student s1 = new Student();
Student s2 = new Student();
System.out.println(s1.equals(s2));

For user-defined classes, equals() can be overridden when equality should depend on object contents rather than references.

Important Point

==       → generally compares references for objects
equals() → can be overridden for logical/content comparison
────────────────────────────────────────────────────────────
6. hashCode() Method
────────────────────────────────────────────────────────────
Syntax: public int hashCode()

# hashCode() returns an integer hash value associated with an object. It is especially important when objects are stored in hash-based collections, such as:

HashMap
HashSet
Hashtable

# Relationship Between equals() and hashCode(). If two objects are considered equal according to equals(), they must return the same hash code.

equals() = true
       ↓
hashCode() must be same

However:

Same hashCode()
       ↓
Does NOT necessarily mean
       ↓
Objects are equal
────────────────────────────────────────────────────────────
7. getClass() Method
────────────────────────────────────────────────────────────
Syntax: public final Class<?> getClass()

# getClass() returns the runtime class of an object.
Example :

class Student {
}
class Main {
    public static void main(String[] args) {
        Student s = new Student();
        System.out.println(s.getClass());
    }
}

It can be used when information about the actual runtime type of an object is required.

Key Point:

getClass()
     ↓
Returns runtime class information
────────────────────────────────────────────────────────────
8. clone() Method
────────────────────────────────────────────────────────────
Syntax: protected Object clone() -> throws CloneNotSupportedException

# The clone() method is used to create a copy of an object. For the standard cloning mechanism, the class generally implements the Cloneable interface.

Example

class Student implements Cloneable {
    int id = 101;
    public Object clone() throws CloneNotSupportedException {
        return super.clone();
    }
}
class Main {
    public static void main(String[] args)
            throws CloneNotSupportedException {
        Student s1 = new Student();
        Student s2 = (Student) s1.clone();
        System.out.println(s2.id);
    }
}

Cloneable
    ↓
Marks that cloning is supported
    ↓
clone()
    ↓
Creates a copy

clone() can throw:

CloneNotSupportedException
────────────────────────────────────────────────────────────
9. finalize() Method
────────────────────────────────────────────────────────────
Syntax: protected void finalize()

# finalize() was historically associated with performing cleanup before an object was reclaimed by the garbage collector.

# Important Modern Java Point: finalize() is deprecated and should not be used for modern resource management.

# Instead, resources should be managed explicitly using appropriate mechanisms such as:  try-with-resources
────────────────────────────────────────────────────────────
10. wait() Method
────────────────────────────────────────────────────────────
Syntax: public final void wait()

# wait() is used in thread synchronization. When a thread calls wait(), it waits until another thread performs an appropriate notification.

Related methods are:

wait()
  ↓
Thread waits
notify()
  ↓
Wakes one waiting thread
notifyAll()
  ↓
Wakes all waiting threads

These methods are associated with an object’s monitor and are normally used within synchronized code.
────────────────────────────────────────────────────────────
11. notify() Method
────────────────────────────────────────────────────────────
Syntax: public final native void notify()

# notify() wakes one thread that is waiting on the same object’s monitor. It is used as part of Java’s inter-thread communication mechanism.
────────────────────────────────────────────────────────────
12. notifyAll() Method
────────────────────────────────────────────────────────────
Syntax: public final native void notifyAll()

# notifyAll() wakes all threads that are waiting on the object’s monitor.

Difference:
notify()
    → wakes one waiting thread
notifyAll()
    → wakes all waiting threads

14. == vs equals()
────────────────────────────────────────────────────────────
This is an important concept when studying Object.

# For objects, == generally checks whether two references refer to the same object.

Student s1 = new Student();
Student s2 = new Student();
System.out.println(s1 == s2);

The result is: false
because s1 and s2 refer to different objects.

# equals() can be overridden to compare the logical contents of objects.

          Object Comparison
                 │
        ┌────────┴────────┐
        ↓                 ↓
       ==              equals()
        │                 │
   Reference          Logical equality
   comparison         when overridden

15. Object Class and Inheritance
────────────────────────────────────────────────────────────
Since every class ultimately extends Object, inheritance forms a hierarchy.

Example:

class Animal {
}
class Dog extends Animal {
}

The inheritance chain becomes:

Object
   ↓
Animal
   ↓
Dog

Therefore, a Dog object inherits methods originating from Object.
────────────────────────────────────────────────────────────
16. Key Points for Exams
────────────────────────────────────────────────────────────
1. Object is the root class of the Java class hierarchy.
2. Every Java class directly or indirectly extends Object.
3. Object provides common methods available to Java objects.
4. toString() provides a string representation of an object.
5. equals() is used for object equality and can be overridden.
6. hashCode() returns a hash value and works closely with equals().
7. getClass() returns runtime class information.
8. clone() is used for object copying through Java's cloning mechanism.
9. wait(), notify(), and notifyAll() are used for thread synchronization.
10. finalize() is deprecated and should not be used for modern resource management.
