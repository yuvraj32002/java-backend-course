============================================================
                 METHOD OVERRIDING IN JAVA
============================================================
1. DEFINITION
--------------
Method Overriding occurs when a child class provides its own
implementation of a method that is already defined in its
parent class.

# In simple words: Same method + Same parameters + Parent-Child relationship
                         ↓
                  Method Overriding

Example:

class Animal {
    void sound() {
        System.out.println("Animal makes sound");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}


Here:
• Animal → Parent class
• Dog → Child class
• sound() → Overridden method
• Dog provides its own implementation of sound()
============================================================
2. WHY METHOD OVERRIDING?
============================================================
Method overriding is used when a child class wants to provide
a specific implementation of a method already provided by
the parent class.

Parent → General implementation
Child  → Specific implementation
============================================================
3. BASIC EXAMPLE
============================================================
class Animal {
    void sound() {
        System.out.println("Animal makes sound");
    }
}
class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}
public class Main {
    public static void main(String[] args) {

        Dog d = new Dog();
        d.sound();
    }
}
Output:
Dog barks

Explanation:
Dog inherits sound() from Animal.
But Dog provides its own implementation of sound().
Therefore, Dog's sound() overrides Animal's sound().
============================================================
4. RULES OF METHOD OVERRIDING
============================================================
Rule 1: Method name must be same
--------------------------------
Rule 2: Parameters must be same
--------------------------------
The following must be the same:

• Number of parameters
• Type of parameters
• Order of parameters

# If parameters are different, it is NOT overriding. It becomes Method Overloading.
------------------------------------------------------------
Rule 3: Return type
-------------------
The return type must be:

• Same, OR
• Covariant

Example:
class Parent {
    Parent getObject() {
        return new Parent();
    }
}

class Child extends Parent {

    @Override
    Child getObject() {
        return new Child();
    }
}
Here:
Parent → Parent
Child  → Child
# Child is a subclass of Parent, so this is called Covariant Return Type.
------------------------------------------------------------
Rule 4: Access Modifier
-----------------------
# The child class cannot reduce the visibility of the overridden method.
Example:
Parent → public
Child  → public       ✓

Parent → protected
Child  → protected    ✓

Parent → protected
Child  → public       ✓

But:
Parent → public
Child  → protected    ✗
# Because protected is more restrictive than public.

# Access level can be: Same OR More Accessible, But NOT Less Accessible.
============================================================
5. @Override ANNOTATION
============================================================
# @Override is an annotation used to indicate that a method is overriding a method of the parent class.

Advantages of @Override:
• Helps the compiler detect mistakes.
• Makes the code easier to understand.
• Clearly indicates that the method is being overridden.

Example of mistake:
class Child extends Parent {
    @Override
    void sho() {
    }
}
# If the parent class does not contain sho(), the compiler will generate an error.

# IMPORTANT: @Override is not compulsory, but it is recommended.
============================================================
6. METHOD OVERRIDING AND RUNTIME POLYMORPHISM
============================================================
# Method Overriding is used to achieve Runtime Polymorphism.
Example:

class Animal {
    void sound() {
        System.out.println("Animal sound");
    }
}
class Dog extends Animal {
    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}
public class Main {
    public static void main(String[] args) {

#       Animal a = new Dog();
#       a.sound();
    }
}
Output:
Dog barks

Here:
# Animal a = new Dog();
# Reference Type  → Animal
# Actual Object   → Dog

# Although the reference is of type Animal, the actual object is Dog.
# Therefore, Dog's sound() executes.
============================================================
7. DYNAMIC METHOD DISPATCH
============================================================
# Dynamic Method Dispatch is the mechanism by which Java determines at runtime which overridden method should be called.

Example:
Animal a = new Dog();
a.sound();

# Flow:
Reference Type
      ↓
    Animal
      ↓
Actual Object
      ↓
     Dog
      ↓
Dog's sound() executes


Therefore:

Method call
     ↓
Runtime
     ↓
Actual Object
     ↓
Overridden Method
# IMPORTANT: Dynamic Method Dispatch is the mechanism behind Runtime Polymorphism.
============================================================
8. USING super WITH METHOD OVERRIDING
============================================================
# Sometimes the child class wants to call the parent class's implementation of the overridden method.

# For this, we use the super keyword.
Example:
class Parent {
    void show() {
        System.out.println("Parent's show()");
    }
}
class Child extends Parent {
    @Override
    void show() {
        super.show();
        System.out.println("Child's show()");
    }
}
Output:

Parent's show()
Child's show()

Here:
# super.show(); calls the parent class's version of show().

Flow:
Child's show()
      ↓
super.show()
      ↓
Parent's show()
      ↓
Child's remaining code
============================================================
9. FINAL METHODS AND OVERRIDING
============================================================
# A method declared as final cannot be overridden.

Example:
class Parent {
#   final void show() {
        System.out.println("Parent");
    }
}
class Child extends Parent {
    void show() {
        System.out.println("Child");
    }
}
ERROR!
final method
     ↓
Cannot be overridden

# IMPORTANT: A final method can be inherited and used by the child class, but it cannot be overridden.
============================================================
10. STATIC METHODS AND OVERRIDING
============================================================
# Static methods cannot be overridden. Static methods belong to the class rather than the object.

Example:
class Parent {
    static void show() {
        System.out.println("Parent");
    }
}
class Child extends Parent {
    static void show() {
        System.out.println("Child");
    }
}

# This is NOT Method Overriding. It is called: METHOD HIDING

# Remember:
# Instance Method → Can be overridden
# Static Method   → Cannot be overridden
============================================================
11. PRIVATE METHODS AND OVERRIDING
============================================================
# Private methods cannot be overridden.
# Reason:
# Private methods are not accessible outside their class and are not inherited by the child class.

Example:

class Parent {
    private void show() {
        System.out.println("Parent");
    }
}
class Child extends Parent {
    void show() {
        System.out.println("Child");
    }
}

# Child's show() is NOT overriding Parent's show(). It is a completely different method.

# Remember:
# private method
      ↓
# Not inherited
      ↓
# Cannot be overridden
============================================================
12. COVARIANT RETURN TYPE
============================================================
# A child class can override a method and return a subclass of the return type declared in the parent class.

# This is called Covariant Return Type.
Example:
class Parent {
    Parent getObject() {
        return new Parent();
    }
}
class Child extends Parent {
    @Override
    Child getObject() {
        return new Child();
    }
}
Here:
Parent method → returns Parent_object
Child method  → returns Child_object

# Since:
# Child IS-A Parent
# The return type is valid.
============================================================
13. EXCEPTION RULES IN METHOD OVERRIDING
============================================================
# While overriding a method, the child class cannot throw a broader checked exception than the parent class.


Example:
class Parent {
    void show() throws IOException {
    }
}
class Child extends Parent {
    @Override
    void show() throws IOException {
    }
}
# This is allowed. Child can:

• Throw the same checked exception
• Throw a narrower checked exception
• Throw no checked exception
• Throw unchecked exceptions

# But:
# Parent → IOException
# Child  → Exception       ✗

# This is NOT allowed because Exception is broader than IOException.
============================================================
14. METHOD OVERLOADING vs METHOD OVERRIDING
============================================================
Method Overloading:
• Same class
• Same method name
• Different parameters
• Compile-time polymorphism
• Inheritance not required

Method Overriding:
• Parent + Child classes
• Same method name
• Same parameters
• Runtime polymorphism
• Inheritance required
============================================================
15. REAL-LIFE EXAMPLE
============================================================
class Employee {
    void raiseSalary() {
        System.out.println("Employee salary increased");
    }
}
class Manager extends Employee {
    @Override
    void raiseSalary() {
        System.out.println(
            "Manager salary increased with incentives"
        );
    }
}
class Engineer extends Employee {
    @Override
    void raiseSalary() {
        System.out.println(
            "Engineer salary increased with bonus"
        );
    }
}
public class Main {
    public static void main(String[] args) {

        Employee e1 = new Manager();
        Employee e2 = new Engineer();

        e1.raiseSalary();
        e2.raiseSalary();
    }
}

Output:
Manager salary increased with incentives
Engineer salary increased with bonus

Here:
# Employee e1 = new Manager();
# Manager's method executes.

# Employee e2 = new Engineer();
# Engineer's method executes.

This demonstrates:
Method Overriding
        ↓
Runtime Polymorphism
        ↓
Dynamic Method Dispatch
============================================================
16. IMPORTANT POINTS
============================================================
1. Method overriding requires inheritance.
2. Parent and child methods must have the same method signature.
3. Method overriding provides Runtime Polymorphism.
4. The method to execute is determined at runtime.
5. The actual object determines which overridden method executes.
6. @Override is used to indicate method overriding.
7. @Override helps the compiler detect mistakes.
8. final methods cannot be overridden.
9. static methods cannot be overridden.
10. private methods cannot be overridden.
11. Child class cannot reduce the access level of the overridden method.
12. Child class can use a covariant return type.
13. super.method() can be used to call the parent class implementation.
14. Child class cannot throw a broader checked exception
    than the parent method.
15. Method overriding is associated with Runtime Polymorphism.
============================================================
